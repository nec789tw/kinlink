# 繫族 (KinLink) ｜ 智慧族譜與祭祖通知系統規格暨部署文件

本文件定義「繫族 (KinLink)」系統之功能規格、資料庫結構與地端離線隨身碟（USB）部署方案。本系統採完全離線、高隱私設計，不依賴網際網路與第三方通訊軟體生態圈。

> **怎麼讀這份文件：** 本文件同時記錄設計目標與目前實作。原本規劃、但**尚未實作**或**已決定不做**的項目，
> 一律在該條直接標明（附決定日期）；沒有標註的敘述都是程式裡現有的功能。
> 最後與程式核對：2026-10-03（版本號以專案根的 `VERSION` 檔為準）。

> **本版修訂重點（交接導向）：** 因管理人員會改選，接手者多半非工程師，本版以「插上隨身碟 → 點開 → 操作 → 安全備份」這條動線能否在不需工程師協助下走完，作為最高設計目標。部署方案由 Docker 改為**免安裝單一執行檔**，存取改用單一「編輯鎖」PIN（不設每人帳號），並補齊備份、還原、匯入匯出等維運機制。

## 1. 專案概述

*   **產品定位：** 輕量化、地端安全、零網路依賴的家族維繫工具。
*   **執行載體：** 網頁技術寫成的介面，封裝為隨身碟內的**單一免安裝執行檔**（`繫族.exe`），雙擊即用、拔插即走。
*   **三大痛點解決：** 傳統族譜難以隨身查閱、年輕一輩不懂複雜親屬稱謂、離線環境下祭祖資訊與集合地點的自動文字轉譯。

## 2. 核心功能模組

### 2.1 族譜管理模組 (Clan Tree Management)
*   **兩種檢視（「族譜」頁上方「列表／樹狀」切換）：**
    *   **樹狀圖：** 適合平板與桌上型電腦，呈現家族世系與姻親。以**手寫 SVG** 繪製（不引入 d3.js 等外部函式庫，維持零相依、離線可用）；可依房頭配色（「設定 → 房頭管理」點各房前的色塊自訂）。分兩種看法（圖上方切換，預設「全族總覽」）：
        *   **全族總覽：** 整棵樹，依螢幕寬度決定預設展開到第幾世（比例不低於 0.6，字看得清楚），點「＋N 人」原地展開下一代；每一世在左側只寫一次，各房起點標房名，配偶寫在框內第二行。
        *   **本支家系：** 以一個人為中心，只畫他的直系祖先（一到兩代，再往上用「往上還有 N 代」）、兄弟姊妹（太多時左右「還有 N 位」）與全部子女；點誰就換看誰的一家。不論家族多大，畫面最多約三、四十人。
        *   圖上方有「縮小／放大／回到預設大小／看全貌／找到選取的人」按鈕，不必會用滾輪。
    *   **列表：** 依世代作為階層，一人一行（姓名、世代、房頭、父名、男女、存歿、生卒年）；點列選人（必要時順便展開），按左側箭頭才收合；窄螢幕也不破版。
    *   兩種檢視共用「目前選取的人」，切換時不會跟丟；族譜頁夠寬時，人物資料卡固定在右側。
    *   **展開：** 列表上方有「全部展開／全部收合」（全族一次攤開或收回）；人物資料卡有「展開這一支（子孫 N 人）」，把選取的人底下的子孫一次展開——列表與樹狀圖都可用，在本支家系按會切回全族總覽。沒有子孫的人不顯示這顆鈕。
*   **人物資料（成員表單）：** 姓名、字號、性別（男／女／不詳）、世代、房頭、父母（親生／過繼／收養）、配偶與婚姻狀態、生年與生日原文、卒年與卒日原文、電話、郵遞區號、現居、掃墓通知寄送對象、安葬資訊（位置描述、安葬型態、穴位／塔位編號）、家族習慣稱呼、備註。父母、配偶欄搜尋人名點了就加入（2026-10-13 起，舊版選了還要再按「＋加」，沒按就存＝孩子沒掛到父母底下）；詳情卡「＋新增子女」帶好父或母、唯一配偶（兩位以上列出點選生母）、世代＝下一世、房頭，可「儲存，再新增一位」；點表單外的遮罩不關表單，只有「取消」（改過先問）才關。
    *   **照片、電子信箱：已決定不做（2026-08-21）**——離線隨身碟不放照片、通知走紙本信函；照片說明、祖籍、事蹟等一律寫在「備註」。schema 裡的 `avatar_url`、`email` 等為保留欄位，程式不讀寫。
*   **在世判定：** 卒年空白、**而且**卒日原文也空白，才算在世（`kinlink/members.py` 的 `_is_alive`）。只記得忌日、不知年份的先人，填卒日原文或勾表單的「已過世（卒年不詳）」，都會存成已過世（卒年欄存哨兵值「已歿」）；CSV 匯入時卒年空白但卒(原文)有記載也一樣。判定在讀取時進行，舊資料庫不必遷移。
*   **日期正規化：** 生年／卒年欄接受 `1928`、`1928-03-12`、`1928/3/12`、全形數字等寫法，存檔時統一成補零的 `YYYY-MM-DD`（只有年份者維持年份）；看不懂的文字（「不詳」、不存在的日期）原樣保留、不拒收。

### 2.2 智慧稱謂計算器 (Kinship Calculator)
*   **相對關係轉譯：** 在「稱謂」頁選取「主體」與「目標」後，系統沿親子邊上溯共同祖先、再查表，輸出雙向稱謂（例如：你該叫他「伯父」；他該叫你「姪子」）。
*   **稱謂查表與習慣代稱：** 演算法以「世系路徑 → 標準稱謂查表」為基礎；成員表單的「習慣稱呼」非空時，優先顯示它（標「家族習慣稱呼」），處理地方叫法不符。
*   **算不出時：** 一律以「族親」相稱，並附白話說明（例如建議補齊父親或母親）；不硬湊稱謂。
*   **目前的計算規則（程式現況，`kinlink/kinship.py`）：**
    *   **長幼：** 兄弟、堂兄弟、伯叔等需要分長幼的稱謂，要雙方（或兩支分歧祖先）生日都判得出先後才給；有人缺生日、同一天、或同年卻只填年份，一律「族親」。
    *   **同宗世代階梯：** 旁系遠近不影響稱謂，以世代差定稱（高一世＝伯叔／姑姑、高二世＝伯公叔公／姑婆…；同世遠房＝族兄弟／族姊妹）。
    *   **姻親橋接：** 一方是嫁入／贅入的配偶時，經其配偶換算（嫂嫂、姑丈、公公、岳父…）；兩方都是配偶時也能算（妯娌、連襟）。
    *   **母系稱謂（外公、舅舅、阿姨、表親）：** 經母親換算，孩子有沒有登錄父親都照算（嫁出女兒的子女、招贅所生都算得出）。表親比照堂親依生日分「表哥／表弟／表姊／表妹」（2026-10-12 總幹事），生日判不出長幼時用通稱「表兄弟／表姊妹」（不推定）。舅舅／阿姨／外甥本來就不分長幼，所以雙方生日缺漏、長幼判不出時，母親的同輩兄弟姊妹（含堂、族；口語堂舅、堂姨也稱舅舅、阿姨）照樣給舅舅／阿姨／外甥。已知不一致：雙方生日都齊全時，母親的堂、族兄弟姊妹目前反而算成「族親」——要統一成「舅舅／阿姨」還是改用「堂舅／堂姨」，待總幹事決定。
    *   **過繼：** 父系鏈優先走過繼、收養的父親（嗣父／養父）；過繼者的本生母與本生父同序——本生父是叔叔，本生母就是嬸嬸（伯父則伯母），不受登錄先後影響；只登錄本生母、沒登錄嗣母時也一樣。寡母改嫁、繼父收養仍是母親；已和本生父離異的本生母、或沒登錄本生父時，仍是母親。
    *   **離異（婚姻狀態「離異」）：** 本人稱前配偶為「前妻／前夫」；離異的婚姻**不再當姻親橋接**（不再是媳婦、嫂嫂）。前妻親生那一支的子孫仍稱她祖母、曾祖母，那一支子孫的配偶也仍是她的媳婦、女婿、孫媳婦；現任配偶那一支不算。
        **因此離異者的子女請在「父母」登錄生母，否則子女對生母的稱謂會變成「族親」**（算不出時，說明文字會點名要在誰的父母欄補登生母）。
*   **通知內文動態代稱：** 通知作業台的訊息模板可用 `{裔稱}`：以活動的「祭祀先人」為準，算出先人怎麼稱呼收件人（裔孫、裔孫女…），整批一次計算（`POST /api/kinship/batch`）。活動沒設祭祀先人、算不出、長幼判不出、或收件人是先人的前配偶時，一律退回通稱「族親」。管理員複製後仍可在手機上人工微調。

### 2.3 祭祖活動與離線通知
*   **祭祖活動：** 「祭祖」頁「新增祭祖活動」：名稱、曆法（國曆／農曆）、日期、祭祀先人（選填；留空＝合祭）、集合地點、備註、通函說明（一行一條，列印自動編號）。活動卡可「列印通知單」「編輯」「複製為明年」；今年以前的活動收在「往年活動」。
*   **農曆活動日期：**
    *   表單農曆欄即時顯示換算後的國曆日期（含民國年）；冬月、臘月落到隔年國曆時醒目提醒（照直覺填「活動那年」會差一年）。
    *   存檔前檢查這一天存不存在（小月沒有三十），不存在就擋下並說明（`POST /api/event` 回 400）；展示模式同樣擋。
    *   擋存之前就已存進庫的不存在日期，活動卡會出現黃色提醒，請按「編輯」改日。
*   **剪貼簿一鍵通知機制（訊息通知作業台）：** 因地端系統無法連接外網 API 發送簡訊，管理員選好活動與通知範圍（全族在世／某房／自訂名單；選「某房」要在旁邊的房頭下拉選一房，沒選會擋下提示）後按「產生通知清單」，系統為每位收件人生成個人化訊息，可逐則「複製」、「複製全部」或「匯出名單 CSV」，由管理員用個人手機手動轉傳。模板佔位符以畫面上的提示為準（`{姓名}` `{活動}` `{國曆}` `{農曆}` `{地點}` `{備註}` `{裔稱}`）。系統**不會**自動發送任何訊息。

### 2.4 列印／輸出模組（核心）

本系統最高頻的實際用途，是每年掃墓祭祖時產生並列印各式制式文件。模組目標：**忠實重現現有各式版型，並統一風格**（統一字體、邊界、協會抬頭；版面不自印頁碼）。

**技術取向（免額外套件）：** 各文件以 HTML 樣板 ＋ 列印用 CSS（`@page`）呈現，由瀏覽器原生「列印／另存 PDF」輸出，不引入 PDF 產生函式庫。所有文件共用一份樣式表（`列印範本/assets/print.css`）與「協會抬頭」區塊（抬頭取自「設定 → 協會資料」）。

**帶自家資料的文件（「列印」頁的卡片 → 選好對象 →「開啟列印頁」；實作在 `webview/print.html?doc=`）：**

| :--- | :--- | :--- | :--- |

*   **寄送對象規則（掃墓通知單、開會通知的合併寄送、信封片頭）：** 全庫只要有人勾了成員表單的「掃墓通知寄送對象」（戶長／代表），就只寄勾選的人；全都沒勾才逐人寄給在世且有地址者。只勾了部分房時，列印頁工具列會列出 0 份的房，查無收件人的訊息也會分清「還沒勾」與「沒住址」。原規劃「會員」與「掃墓族親」兩份名單：**未實作**，改由這個勾選取代。
*   **版式示範：** `列印範本/` 另有通知函、寄信封面標籤、通知名單、族譜表、牌位姓名表、穴排位圖等靜態範本（內容全為虛構示範資料）。列印頁不再列出（2026-10-06：名稱跟上面的卡對不起來、點了會印到假資料）；**展示模式**（沒有後端）按各卡的「開啟列印頁」就開對應的範本，開會通知沒有範本。

**忠實重現要點（避免失真）：**
*   日期須能同時呈現**西元年 ＋ 歲次（干支）＋ 年號（清領各朝）＋ 農曆月日**，缺者顯示「欠載」。為此 `members` 增設 `birth_date_original`／`death_date_original` 逐字保留原始記載，列印時再拆欄：
    *   **歲次：** 有完整國曆日期時先換成農曆年再推干支（元旦到春節之間出生的人歲次是前一年）；只填西元年或 1900 年以前時，優先採原文年號旁明寫的干支。
    *   **年號／農曆月日：** 「光緒27年臘月廿六」拆成 光緒27年／臘月廿六；年號後緊接的干支（含「干支＋年」連寫）略去，月日欄不殘留「年」；「道光年間」「民國三十八年生」這類原文整段歸年號欄（併回時同樣略去干支：「民國十七年戊辰生」→ 民國十七年生）；「年」後面有數字、月日字樣、時辰或節氣的仍算月日（「民國17年2/21」→ 民國17年／2/21）。
*   姓名保留字號括號（如 `楊文遠(字號)`，示範用虛構名）；地名保留新舊雙寫（如 `舊地名(今行政區名)`）。
*   `〇〇`、「欠載」等原始標記照實保留，不自動清空。
*   牌位／穴排位之男女敬稱格式（某公／某氏）由列印樣板套用，資料端只存姓名與性別。

### 2.5 墓葬場地與穴排位（場地格線）

各家族的墓葬場景差異極大（傳統祖墳、納骨塔、樹葬…），且傳統昭穆口訣本身存在互相矛盾的慣例（奇數居左 vs 二四六居左），故本系統**不做全域排位規則引擎**，採一條原則：**「位置是資料，版面是每個場地自己的設定」**。

| 場景 | 位置形態 | 處理 |
| :--- | :--- | :--- |
| 傳統祖墳 | 世代 × 左右對稱穴位 | 場地格線：列＝世代、格＝穴位 |
| 納骨塔 | 樓／區／排／號 | 同一套格線，列標籤改為樓／排 |
| 樹葬・海葬・其他 | 無固定「位」 | 僅記地點文字，不進格線 |

*   **原文位置碼＝權威：** `tombs.detail_location_code` 逐字保留原始記載（如「3樓忠區5排12號」「第二排左3」），永不失真——與生卒日期「保留各式」同一哲學。
*   **場地（site）自訂格線：** 每個墓域／塔為一個場地，管理員自訂格線（幾列×幾格、列標籤文字），再把成員指到格位。版面屬於場地設定，非程式規則；換家族、換塔自畫格線即可用（與「房頭可設定」同一精神）。
    **實作（2026-08-21）：** 資料表 `tomb_sites`（一列＝一張可列印的格子表；`cells` 為 JSON，`memberId` 指成員、`text` 自由文字），模組 `kinlink/tombsites.py`，畫面「穴排位」頁（點格子選人／打字、CSV 匯出匯入，CSV 須為 UTF-8），列印 `print.html?doc=tombgrid&site=ID|all`。格子稱呼自動套「字號　姓公／名　姓氏」，手改文字優先。葬在場地外者不進格線，靠 `tombs` 文字欄。切換場地時若有未存的修改，會先詢問。
    **版型（2026-10-12，照家族的穴排位圖）：** 場地可選三種版型（`tomb_sites.layout`＋`layout_opts`）——
    **方格**（原本，列標籤在左）、**面板**（幾塊紅框格子並排，各塊列數可不同，例「每塊 3 欄、14,11,11,14 列」）、
    **階梯**（主牌位：一層比一層寬、置中，由右往左直書，例「12,12,16,21,25 格」）。面板與階梯的列數欄數由設定推出。
    每格另有「上方小字」（`cells[].top`，多半寫世代）：面板印在名字上方；階梯相鄰同字合成世代橫條，橫條字由右往左排
    （原圖「世 三 十」＝十三世）。只寫上方小字、名字留白的預留格照樣保存列印。紅底用 `print-color-adjust: exact`，
    不必另勾「背景圖形」。
    **Excel（CSV）來回：** 方格＝第一欄列標籤、其餘格子文字（匯入時尺寸跟著 CSV）。面板／階梯（2026-10-12）＝紙上怎麼排 Excel 就怎麼排：
    一層（階梯）／一列（面板）佔兩列，上面「世代」（格子上方小字）、下面「名字」，第一欄寫「第1層・世代」「第1層・名字」；
    由左到右照紙上的順序（階梯紙上由右往左讀，Excel 最左＝那層最後一格）；面板幾塊之間空一欄；名字「○」＝空位（匯出時每個空位都標 ○，
    Excel 看得出形狀）。匯入只填格子、不改版型與格數；填到圖外（超過那層格數、面板之間的空白欄、某塊沒有的列）整批 400 並講出哪一層哪一欄，
    原格子不動。名字比對：姓名、字號或稱呼唯一者連到族親；同名不只一位時再用上方小字的世代（十三世／第13世）分辨，仍分不出就存成文字。
    畫面上有沒存的修改時不准匯出／匯入（形狀會對不上、匯入後重讀會蓋掉）。展示模式只示範方格的 CSV。
    **示範資料**：方格、階梯（主牌位放先人）、面板（放後代＋神位）各一張，清空示範時三張照同一套「沒動過才刪」規則。
    **app 畫面＝列印（2026-10-12 總幹事：列印看很直覺，app 要照列印重新設計）：** app「穴排位」頁與列印頁用同一套畫法
    （`webview/js/tombdraw.js`＋`webview/css/tomb.css`），格子畫成一張白紙放在最上面，抬頭、地址、日期、紅框、世代橫條都跟印出來一樣，
    點格子編輯；紙張至少 A4 橫式寬（格子少的場地抬頭、地址、日期也照列印排在兩側），比畫面寬時整張等比縮小（不擠扁格子）。面板、階梯的名字超過 4 個字（自動稱呼「字號　姓公」就是 5 個字）自動縮字放進格子，列印與 app 同一套。灰字＝自由文字、沒連到族譜裡的人（印出來仍是黑字）。版面設定放在紙張下面，
    改抬頭、日期、地址、尺寸時紙張即時重畫。
*   **昭穆建議位置：已決定不做（2026-08-21）**——各家慣例互相矛盾，排位一律由管理員自己指定。
*   **列印：** 穴排位圖樣板依場地格線照實輸出，任何場景通用。

## 3. 存取模式（編輯鎖）

隨身碟由管理委員會實體持有，持碟者即為受信任的編輯者。系統**不設每人帳號，亦不做資安等級的權限分級**——離線隨身碟上任何人皆能以 SQLite 工具直接讀取 `.db` 檔，App 密碼無法提供資料防護。故僅以單一「編輯鎖」防止手滑誤改／誤刪：

| 模式 | 說明 |
| :--- | :--- |
| **瀏覽模式（預設）** | 開啟即進入。可瀏覽族譜、使用稱謂計算器、查閱祭祖活動、列印、產生通知清單、立即備份、檢查更新。不需密碼。 |
| **編輯模式** | 點左下角「瀏覽模式」輸入共用「編輯鎖 PIN」解鎖，並選擇編輯範圍（某一房，或「全部（委員）」）後，才能新增／修改／刪除成員與親屬關係、祭祖活動、穴排位場地，修改設定（主題與介面縮放除外），匯入 CSV、還原備份、清空示範資料、下載更新。<br>**解鎖後不會自動逾時：** 用完請按左下角「編輯中」（或頂部狀態列的「完成，鎖定」）手動上鎖，或直接關閉程式。（閒置自動上鎖**已決定不做（2026-10-02）**：前端無法處理被動上鎖，做了反而讓使用者在編輯到一半時看到莫名的錯誤。） |

*   **PIN 性質：** 編輯鎖只防誤觸，非資安機制。PIN 明文存於 `settings` 表（`edit_pin`，出廠 `0000`），並寫在交接單上。變更：「設定 → 編輯鎖 → 設定／重設 PIN」，需輸入目前 PIN。
*   **房頭護欄（掃墓現場多人編輯）：** 掃墓時帶筆電到場，讓各房當場更新自己那一房（新生、嫁娶、過世、電話等）。解鎖時選定某房，系統只准修改「房頭」欄等於該房的成員（親屬增刪以子女端為準），避免誤動他房；鎖定單一房時不可匯入 CSV。此為操作護欄非資安機制，採榮譽制，不為各房另設密碼；`members.branch` 即判定依據。委員選「全部」不受限。
*   **解鎖自動快照：** 每次解鎖成功，系統先把現況存一份「編輯前」快照到 `backups\`（`編輯前_日期_時分秒.db`，保留最近 5 份）；當場若改壞，可用「還原備份」選這份檔回到解鎖前的狀態。配合「名下仍有子女者不可刪除」，降低現場誤刪風險。
*   **忘記 PIN：** 程式內無法自行重設。請會用電腦的人以 SQLite 工具開啟 `繫族.db`，把 `settings` 表的 `edit_pin` 改回 `0000`（操作手冊與交接單都有寫）。原規劃隨身碟附「重設編輯鎖.exe」：**尚未實作**。
*   **交接：** 交付隨身碟 ＋ 交接單（含 PIN）＋ 操作手冊即完成，無帳號、無審核流程。

## 4. 全場景與邊界狀況分析 (Edge Cases)

### 4.1 多元家庭與複雜婚姻結構
*   **再婚、離婚與多元配偶：** 資料庫放棄一對一死綁定。單一成員可建立多段婚姻關係，並獨立標記婚姻狀態（婚姻中、離異、喪偶、分居）。子女屬於哪一段婚姻，以**母親邊**表達：子女直接連到親生母親（`relationships` 的女性親代），即可分辨是哪段婚姻所生，稱謂引擎也因此算得出舅舅、外公、表兄弟等母系稱謂；繼母不連親子邊，必要時寫在備註。（2026-09-11 決定不採用原設計的 `relationships.marriage_id`——實查本譜，有兩段以上婚姻且育有子女者，其子女都沒有記載生母，欄位開了也填不進去；該欄保留於 schema，業務程式不讀取。）
*   **離異的稱謂：** 離異的婚姻不再橋接姻親稱謂（詳見 §2.2）。**離異者的子女請登錄生母，否則子女對生母的稱謂會變成「族親」。**
*   **同性婚姻：** 婚姻表以 `spouse_1_id` 與 `spouse_2_id` 記錄，不限配偶性別。稱謂查表以傳統稱謂為主，不合用時請用成員表單的「習慣稱呼」覆寫。
*   **收養與過繼：** 系統採用「血緣」與「法定/禮法」雙軌制。單一成員允許同時綁定「本生父母」與「嗣父母/養父母」，以 `relationships.relation_type` 區分（親生 / 過繼 / 收養），成員詳情以標籤標示關係型別。稱謂計算時父系鏈優先走過繼／收養邊（嗣父母），本生父母依 §2.2 換算。

### 4.2 時間與曆法衝突
*   **生卒曆法：** 長輩常見生日記國曆、忌日記農曆。實作以兩條軌道並存：可換算的國曆日期存 `birth_date`／`death_date`（供排序、長幼、換算），族譜原始記載（含農曆月日、年號、干支）逐字存 `birth_date_original`／`death_date_original`（供忠實列印）。原設計的 `birth_calendar`／`death_calendar` 欄位保留於 schema，程式不讀取。
*   **農曆換算：** 透過**現成離線農曆函式庫查表**（實際採用 `borax`，MIT 授權——原用的 lunardate 為 GPLv3，打包進散布的 exe 會與本專案 MIT 衝突），不自研萬年曆。查表範圍 1900–2099；範圍外或換算失敗時優雅退回原文，不影響其他功能。用途：表單即時農曆對照、祭祖活動國↔農換算與日期存在性檢查、歲次干支。
*   **農曆閏月忌日：** `members.death_is_leap_month` 與 `settings.leap_month_reminder` 僅作資料保留。
    **（2026-08-21 總幹事決定：不做「忌日提醒」功能。** 本譜為家族合墓、統一掃墓，逐人忌日提醒多餘；設定頁的功能開關已移除。）
    **（2026-09-04 追加決定：「掃墓提醒」也不做。** 家族一年一次統一掃墓、活動由總幹事手動建立，不需要系統倒數；設定頁「選用功能」區四個預留開關全數結案後整區撤除。）
*   **掃墓週期：** 設定頁「祭祖習俗 → 掃墓週期」下拉選擇本家族習俗（清明、三日節、客家掛紙、冬至、自訂日期），存於 `settings.sweep_cycle`，只記錄習俗、供通函措辭參考，不能填具體日期、也不做提醒；實際日期由每場祭祖活動決定。修改需編輯模式。

### 4.3 操作限制
*   **宗族同名同姓防呆：** 家族中常有字輩相同導致同名同姓之情況。系統在搜尋、列表、選人器中，於姓名前串接識別標籤。格式為：`第N世·房頭·[外姻標註·]父名-姓名`（範例：第三世·長房·楊建華-楊承恩，示範用虛構名；世代用中文數字，2026-10-03 起由「代」改「世」）。房頭空白或「本宗」、無父名時略去該段，不報錯。搜尋另做姓名異體字折疊（如 廸＝迪、峯＝峰）。

### 4.4 隱私安全與防止熱插拔損壞
*   **隨身碟突發性拔除防護：** SQLite 資料庫全面啟用 `WAL (Write-Ahead Logging)` 模式，降低因使用者直接拔除隨身碟而導致資料庫損毀的風險。
*   **關閉程式：** 按視窗右上角「×」關閉即停止本機伺服器、結束程式。沒有 WebView2 而改用瀏覽器開啟時，繫族會跳出「用完請先關瀏覽器，再按『確定』結束」的訊息框，按下「確定」才結束（按之前不要拔隨身碟，也不能套用更新）。原規劃介面上另設「安全關閉系統並退出」按鈕與拔碟提示：**尚未實作**，以上述關閉方式代替；仍請使用者勿在程式執行中直接拔碟。
*   **檔案系統相容性：** 系統包不含超過 4GB 的單一檔案，在舊型 FAT32 或主流 exFAT/NTFS 隨身碟上皆能讀寫（不存照片，見 §2.1）。
*   **放在不可寫的位置：** exe 放在 `C:\Program Files` 這類系統資料夾、唯讀隨身碟或防寫的 SD 卡時，程式會跳出中文說明（請把整個資料夾複製到隨身碟、桌面或「文件」再開）後結束；從 zip 裡直接執行（會落在 Windows 暫存區）也會先擋下並說明。

## 5. 維運與交接機制 (Operations & Handover)

> 本節為本系統能在管理人員改選後持續運作的關鍵，所有項目均須在介面上以非工程師看得懂的方式提供。

*   **一鍵備份：** 「設定 → 資料 →『立即備份』」（瀏覽模式也可按）。後端以 `VACUUM INTO` 產生已合併 WAL 的單一 `.db`，存進資料庫旁的 `backups\` 資料夾，檔名 `繫族-備份-YYYYMMDD-HHMMSS.db`（同一秒重複時加 `-2`）。**禁止以直接複製作用中 `.db` 檔作為備份手段**（WAL 模式下會拿到缺最近改動的舊資料）。
*   **自動備份：** 一律存進 `backups\`：
    *   `自動備份_YYYY-MM-DD.db`：每次啟動程式（同日覆蓋），保留最近 5 份；
    *   `編輯前_YYYY-MM-DD_HHMMSS.db`：每次解鎖編輯（§3），保留最近 5 份；
    *   `繫族-備份-*.db`：「立即備份」、還原前、清空示範前產生，不自動刪除；
    *   `繫族-備份原檔-*.db`：還原或清空示範前，若現有庫已損壞、無法用 `VACUUM INTO`，改為原封複製。
    *   匯入 CSV 前**沒有**另外的自動快照：大量匯入前建議先按「立即備份」（解鎖時的「編輯前」快照也可退回，但會連同解鎖後的其他修改一起退回）。
*   **一鍵還原：** 「設定 →『還原備份』」（需編輯模式）→ 選一份備份檔（`.db`，任何位置皆可，通常在 `backups\`）→ 確認。後端先驗 SQLite 檔頭、`PRAGMA integrity_check`、必備資料表，並對備份套用本版資料結構（舊版備份也能還原、還原後不必重開）；任一關不過就回「這不是完整的繫族備份」，現有資料庫完全不動。覆蓋前自動備份現況（備份失敗就中止還原），最後以原子替換換上。
*   **匯入：** 「設定 →『下載匯入範本』（CSV）→ 用 Excel 依表頭填寫、另存為『CSV UTF-8』→『匯入 CSV』→ 預覽 →『確認匯入』」（需編輯模式，且解鎖時房頭選「全部」）。只收 UTF-8（含 BOM）。預覽報告列出新增／更新／錯誤筆數，以及「更新列提醒」「Excel變形提醒」（疑似被 Excel 改壞的欄位）「同名提醒」「改為已歿提醒」（原本在世、匯入後會改成已過世、不再收到在世通知的人）「新增房頭」。
*   **匯出：** 「設定 →『匯出 CSV（Excel 可開）』」輸出成員清冊，兼作通用備份，避免被單一隨身碟綁架。匯出 Excel（.xlsx）或 PDF 清冊：**尚未實作**（API 回 501）；要紙本或 PDF 請用列印頁（§2.4）。
*   **示範資料（首次使用）：** 全新資料庫第一次開啟時灌入一小份虛構示範資料（楊家），並在畫面頂端顯示引導條。解鎖編輯後，「設定 →『清空示範資料』」只刪示範列（人物、活動、場地），使用者自己建立的資料一律保留，清空前自動備份；示範房頭（長房、次房）若已沒有成員使用，會從房頭清單拿掉，其他房頭原樣保留。清完後按鈕與引導條消失，之後也不會再灌回示範。
*   **操作手冊（交付物）：** `列印範本/操作手冊.html`，在程式內左邊選單「關於 →『開啟手冊』」開啟，可印成 A4 或另存 PDF，涵蓋開機、關機、備份還原、編輯鎖 PIN、列印、通知作業台、成員編輯、檢查更新、第一次使用與交接。原規劃系統內常駐「使用說明」分頁：**未實作**，以操作手冊與首次使用引導條代替。
*   **交接單（交付物）：** `列印範本/繫族交接單.html`（列印頁「會務文件」區的「交接單（印出手寫）」），印出後手寫：現行 PIN、軟體發佈來源（GitHub owner/repo）、能發佈新版的人、隨身碟正本與備用副本放哪、家族原始文件放哪、移交與接手人、技術協力親友。

## 6. 部署方案 (Deployment)

*   **封裝形式：** 以 Python + PyInstaller 打包為**單一免安裝執行檔**（`--onefile`），內嵌標準庫 HTTP 伺服器、SQLite 與前端資源。**不使用 Docker**——一般家族幹事的 Windows 不會預裝 Docker Desktop，無法達成「插拔即用」。
*   **啟動方式：** 雙擊 `繫族.exe`：在本機起伺服器（只綁 `127.0.0.1`、隨機埠、隨機通行碼），用系統內建的 WebView2 開一個原生視窗。電腦沒有 WebView2 時改開預設瀏覽器（結束方式見 §4.4）。免安裝、免系統權限、免虛擬化。（舊稿的「點我啟動.exe ＋ 開預設瀏覽器」已由此取代。）
*   **資料位置：** 資料庫 `繫族.db` 與 `backups\` 都在 exe 旁邊，整個資料夾複製即完成搬遷與交接。
*   **更新：** 「關於 →『檢查更新』」只在按下時連網，比對發佈來源（預設官方 GitHub repo，可改成自己 fork 的 owner/repo）的最新 release。有新版時「下載更新」（需編輯模式）把新版存成 `繫族_new.exe` 並產生 `套用更新.bat`；使用者關閉繫族後雙擊 bat 完成換版：
    *   繫族還開著會提示並等待（約 30 秒）；仍沒關就放棄，檔案一個都不動；
    *   舊版保留為 `繫族-舊版.exe`（下次更新覆蓋）；新版有問題時，把新的改名或刪掉、再把舊版改回 `繫族.exe` 即可；
    *   舊版程式檔被防毒軟體占用、改名失敗時，什麼都不會變動，稍後再雙擊一次即可；上次換到一半中斷（只剩 `繫族.exe.old` 或只剩舊版）時會先自動救回；
    *   資料夾名稱含 `%OS%` 這類前後都是 `%` 的字樣時，Windows 在裡面執行不了 .bat，按「下載更新」會直接提示先把資料夾改名；
    *   下載只接受 GitHub 網域，並比對檔案大小與 release 登記的 sha256（有登記時）；下載中斷會清掉半截檔、回白話訊息，目前的程式不受影響。
*   **原始碼保存：** 原規劃另存原始碼壓縮檔於隨身碟：**尚未實作**。原始碼以公開 GitHub repo（MIT）保存，交接單記下發佈來源與能發佈新版的人。

## 7. 資料庫核心實體關係 (SQLite Schema)

> **schema 的唯一權威是程式碼：[`db.py`](../db.py) 的 `_SCHEMA` 常數（建表）與其後的
> `ALTER TABLE` 輕量遷移。** 本節刻意不再複製 SQL——過去複製的版本與實作漂移過
> （曾列出從未實作的 `burial_sites` 表與 `tombs.site_id/grid_row/grid_col` 三欄，
> 也漏掉 `note`／`postal_code`／`letter_body`／`mail_target` 等後續加的欄位），
> 照抄的人會直接踩到 `no such table` / `no such column`。要看實際欄位請執行：
>
> ```bash
> python -c "import db,tempfile,os; p=os.path.join(tempfile.mkdtemp(),'t.db'); db.init_db(p); c=db.connect(p); [print(r[0]) for r in c.execute(\"select sql from sqlite_master where type='table'\")]"
> ```

七張表與各自的職責：

| 表 | 職責 | 重點欄位 |
| --- | --- | --- |
| `members` | 成員主檔 | 姓名、字號（`generation_name`）、世代、房頭、性別、生卒（國曆＋原始記載雙軌）、聯絡、備註、`mail_target`（掃墓寄送對象）、`custom_kinship_term`（家族習慣稱呼） |
| `marriages` | 婚姻 | `spouse_1_id`／`spouse_2_id` 去性別化、`marriage_status`（`MARRIED` 婚姻中／`DIVORCED` 離異／`WIDOWED` 喪偶／`SEPARATED` 分居）；選填 `spouse_role`（原版配偶身分：續、再續、側室、妾、招贅、入贅；空白＝元配） |
| `relationships` | 親子邊 | `relation_type` 雙軌：`BIOLOGICAL`（親生）／`ADOPTED`（過繼）／`FOSTER`（收養）；同一子女可並存本生與嗣父母；選填 `orig_label`（子女在父親那張原表上的稱呼，如「三男」「長男(螟蛉子)」「三女(嗣胡)」「養女」）、`sib_order`（家族記載的子女順序） |
| `tombs` | 安葬 | `tomb_type`（土葬／塔位／樹葬）、`address_description`（地點文字）、`detail_location_code`（穴位／塔位編號） |
| `ritual_events` | 祭祖活動 | 名稱、`deceased_member_id`（祭祀先人，可 NULL＝合祭）、`target_date`＋`calendar_type`（國曆／農曆）、集合地點、備註、`letter_body`（通函說明） |
| `tomb_sites` | 穴排位場地格線（§2.5） | 一列＝一張可列印的格子表：`rows`／`cols`／`row_labels`(JSON)／`cells`(JSON，格子指成員或自由文字，可帶上方小字 `top`)／`layout`（grid／panels／steps）／`layout_opts`(JSON) |
| `settings` | 全域設定 | 鍵值對：`edit_pin`（編輯鎖 PIN）、`branches`（房頭清單，JSON）、`branch_colors`（房頭配色，JSON）、`sweep_cycle`（掃墓週期）、`org_*`（協會資料）、`gen_base`（信封支系標註起算世代）、`github_repo`（發佈來源）、`meeting_notice`（開會通知內容，JSON）、`notice_template`（通知作業台的訊息模板）、`theme`／`ui_zoom`（主題與介面縮放，免解鎖即可改、存在資料庫、重開沿用）、`demo_data`／`demo_manifest`（示範庫標記，只由程式寫） |

設計原則：

*   **不做軟刪除**：族譜是長期資料，刪除一律實刪並靠自動備份保底（見 §5）。
*   **刪除護欄**：親子、婚姻邊的外鍵為 `RESTRICT`；名下仍有子女的成員不可刪除（先改子女的父母或先刪子女）。刪除成員時，本人作為子女／配偶的邊一併清除，墓葬隨之刪除（`CASCADE`），以他為祭祀先人的活動改為合祭（`SET NULL`）。
*   **輕量遷移**：新欄位以 `ALTER TABLE ... ADD COLUMN` 於 `init_db()` 內冪等補上，
    既有資料庫免重匯即可升級（重匯會覆蓋使用者在 App 內的編輯，不可行）。
