# 繫族 KinLink ｜ 執行與打包說明（Runbook）

這份說明寫給「不是工程師」也能照著做的人。三種使用情境，由淺入深：

| 我想做什麼 | 看哪一節 | 需要先裝東西嗎 |
| --- | --- | --- |
| 只想看看畫面長怎樣、點點看 | **A. 開發預覽** | 不用，雙擊即可 |
| 想從原始碼實際跑（會存資料、會記住） | **B. 原始碼執行** | 需要 Python 與相依套件 |
| 想做成一個 .exe，發給家人用 | **C. 打包成 exe** | 需要 64 位元的 Python 3.10～3.13（打包一次即可） |

> 只是要「用」繫族的家族總幹事，不必看這份：到 GitHub Releases 下載 `kinlink-vX.Y.Z-win-x64.zip`，
> 解壓後雙擊 `繫族.exe`，照 zip 裡的 `先看我.txt` 做即可。

---

## A. 開發預覽（最快，看設計稿）

**用途**：純粹看畫面、體驗操作流程。資料是「楊家虛構示範資料」，**改了不會存**，重新整理就還原。適合給家人先看看樣子、確認排版。

**怎麼做**：

1. 打開檔案總管，進到本資料夾裡的 `webview` 資料夾。
2. 對 `index.html` 按右鍵 →「開啟檔案的應用程式」→ 選 Chrome 或 Edge 瀏覽器。
   （或直接把 `index.html` 拖進已開啟的瀏覽器視窗。）
3. 畫面就會出現，頂端有「展示模式」橫幅；可以直接點選、切換、查稱謂、看示範通知。

**原理**（不需懂）：網址列開頭會是 `file://`。前端的橋接層 `bridge.js` 偵測到沒有後端，
就自動切到「展示模式（mock）」，用內建的楊家假資料讓你離線預覽，**不會碰到你電腦上的任何真實資料**。

> 注意：展示模式下的「儲存／刪除」只存在記憶體，重新整理就回到原狀；帶自家資料的列印頁需要後端，
> 展示模式按列印頁各卡的「開啟列印頁」，開的是對應的版式示範（`列印範本/`，虛構資料）。
> 要真的存資料，請走 **B** 或 **C**。

## B. 原始碼執行（真的會存資料）

**用途**：工程師試跑、開發。會啟動一個只在你自己電腦上跑的小型後端，把資料存進一個資料庫檔，
關掉再打開資料都還在。

> ⚠ 原始碼模式讀寫的是**專案資料夾裡的 `繫族.db`（開發用）**，不是 exe 旁邊那份正式資料。
> 畫面頂端會常駐一條警示，提醒你正在用原始碼模式。

### 第一次要先準備環境（只需做一次）

1. 安裝 **Python 3.10 以上**（到 python.org 下載，安裝時請勾選「Add python.exe to PATH」）。
   只要跑原始碼，3.14 也可以；要**打包**才有版本限制（見 C 節）。
2. 開啟「命令提示字元」或「PowerShell」，切到本資料夾，輸入：

   ```
   pip install -r requirements.txt
   ```

   這會裝兩個直接相依的套件（以及它們自己需要的套件）：
   - `pywebview`：用 Windows 內建的 Edge WebView2 元件開一個像 App 的原生視窗。
   - `borax`：農曆／國曆換算（MIT 授權；早期用的 lunardate 是 GPLv3，打包散布會和本專案的 MIT 衝突，所以換掉——**不要裝回 lunardate**）。

   （其餘像資料庫、網頁伺服器都是 Python 自帶的，不用另外裝。）

### 每次要用時

三種啟動方式擇一：

| 方式 | 做法 | 特性 |
| --- | --- | --- |
| 雙擊 `工程師用-原始碼試跑.bat` | 檔案總管裡雙擊 | 用 pythonw 啟動，不留黑色命令列視窗 |
| `python app.py` | 在命令列輸入 | 跟 exe 同一套啟動流程，訊息印在命令列 |
| `python server.py` | 在命令列輸入 | 只起後端並用預設瀏覽器開啟（開發／手動測試用），按 Ctrl+C 結束 |

`app.py` 啟動後會：

1. 自動建立／開啟資料庫檔 `繫族.db`（就放在這個資料夾裡），並自動備份一份到 `backups\`。
2. 資料庫是全新的時候，自動載入一份楊家虛構示範資料，方便你直接上手；之後就用你自己的資料。
3. 跳出一個 **原生視窗**（標題「繫族 KinLink」），所有編輯都會真的存檔。

**關閉**：直接關掉那個視窗，程式會自動把後端收掉、釋放資源，乾淨結束。

> 如果電腦沒有「Edge WebView2 元件」，程式不會卡住——它會改用你的**預設瀏覽器**打開：
> - 用 `python app.py` 在命令列跑時，命令列會提示「完成後按 Enter 結束」；
> - 用 `工程師用-原始碼試跑.bat`（沒有命令列）或打包好的 `繫族.exe` 時，會跳出訊息框
>   「用完請先關瀏覽器，再按『確定』結束」。
>
> 按下 Enter／「確定」之前程式都還在執行：不要拔隨身碟，也不能套用更新。

### 我的資料存在哪？會不會外洩？

- 全部存在 `繫族.db` 單一檔案裡（原始碼模式在專案資料夾；exe 在 exe 旁邊）。程式內「設定 → 資料」會顯示完整位置。
- 備份一律在同一資料夾的 `backups\` 裡（見下方 FAQ）。
- 後端**只綁定 127.0.0.1（你自己的電腦）**，外面的人連不到，也不會跳防火牆警告。
- 另有一道隨機通行碼（token）：每次啟動都重新產生，只有那個視窗自己知道。
- 程式平常完全不連網；只有按「關於 → 檢查更新」與「下載更新」時才會連 GitHub。

## C. 打包成 exe（做成一個檔，發給家人）

**用途**：把整套東西包成**一個 `繫族.exe`**。對方電腦**不必裝 Python**，雙擊就能用；
放到隨身碟也能帶著走（可攜）。

### 打包需要的 Python

打包工具（PyInstaller 6.10.0、pythonnet）只支援 **64 位元的 Python 3.10～3.13**，建議 **3.12**（發行版就是用它打包驗證的）。
3.14、32 位元版、ARM64 版都不會被選中；電腦上可以同時裝 3.12 與 3.14，互不影響。

### 打包步驟

1. 在本資料夾**雙擊 `build_exe.bat`**（或在命令列執行它）。
2. 它會自動：
   - **挑 Python**：先問 py 啟動器電腦上裝了哪些版本，依 3.12 → 3.13 → 3.11 → 3.10 挑第一個 64 位元版；
     沒有 py 啟動器才看 PATH 上的 `python`。找不到合用的版本會印出中文說明並停下
     （說明文字在 `release\build-help-no-python.txt`）。
   - **建打包用虛擬環境 `build_venv\`**：已經有的話先檢查它的 Python 版本與位元數，不合就停下並請你把 `build_venv` 資料夾刪掉重跑
     （說明文字在 `release\build-help-bad-venv.txt`）。
   - **安裝套件**：`requirements.txt` 加上打包工具，一律以 `constraints.txt` 鎖住每個套件（含傳遞相依）的版本，換一台電腦也打出一樣的內容。
   - **跑完全部測試才打包**：`tests\smoke.py` 與 `tests\test_*.py` 逐支執行，任何一支失敗就中止。
     （`tests\` 只在維護者電腦上，公開原始碼不附；沒有 `tests\` 時照樣打包，結尾的 SKIP 彙總會註明這次沒有測試把關。）
     每支測試的輸出即時顯示在視窗，同時存到 `build_venv\test-logs\<名稱>.log`。
   - 依 `繫族.spec` 用 PyInstaller 把程式、前端畫面、列印範本全部打進 `dist\繫族.exe`。
   - **實際啟動一次**：`dist\繫族.exe --selftest build_venv\selftest.log`。在暫存資料夾建臨時資料庫、起本機伺服器、
     打首頁、列印頁與幾支 API，並載入原生視窗元件（pywebview、.NET 互通層、WebView2 組件）；不開任何視窗、
     不碰 `dist\繫族.db`。結束碼 0＝全部通過、1＝有項目失敗、9＝逾時；報告內容會印在 build 視窗。不是 0 就判定失敗、不能發佈。
   - **產生發佈檔**（`release\make_zip.py`）：見下方「產出在哪」。
3. 看到 **BUILD SUCCESS** 字樣就完成了。結尾會列出這次被 SKIP（略過、沒有真的驗到）的測試，例如沒有 node 或 Edge 時的前端測試；
   全部都有跑會寫「Skipped tests: none」。

### 產出在哪、怎麼用

- `dist\繫族.exe`：單一執行檔本體。
- `dist\kinlink-vX.Y.Z-win-x64.zip`：給一般人下載的包（`繫族.exe`＋`先看我.txt`＋`LICENSE`＋`THIRD-PARTY-NOTICES.txt`）。
  瀏覽器與公司網路常擋裸 `.exe` 下載，zip 幾乎都拿得到。
- `dist\kinlink-vX.Y.Z-win-x64.exe`：和 `繫族.exe` 同一個檔，給程式內「檢查更新」用（更新器只認 release 的 `.exe` 附件）。
  **發佈新版時兩個都要上傳到 GitHub Release。** 版本號 `X.Y.Z` 取自專案根的 `VERSION` 檔，發版只改這一處。
- `THIRD-PARTY-NOTICES.txt`：依 PyInstaller 這次的分析結果（`build_venv\pyi-build\繫族\PYZ-00.toc`、`PKG-00.toc`）
  只列實際打包進 exe 的套件與授權全文（沒附授權檔的 MIT 套件補上標準 MIT 全文）；讀不到分析結果時退回列 build_venv 全部套件並印 WARN。
- **可攜**：`繫族.exe` 複製到隨身碟或任一可寫入的資料夾都能直接雙擊執行；
  它會把資料庫 `繫族.db` 與 `backups\` 建在 exe 旁邊，資料跟著資料夾走。
  不要放進 `C:\Program Files` 這類系統資料夾（寫不進去，程式會跳中文說明後結束）。

> 小提醒：第一次雙擊新下載的 .exe，Windows 可能會出現藍色「SmartScreen」提示，
> 點「其他資訊」→「仍要執行」即可（因為這是自製、未經商業簽章的程式，屬正常現象）。

## D. 測試

全部測試都在 `tests\`，純標準庫、離線、用臨時資料庫，跑完自己清掉暫存（`tests\_tmpclean.py`）。
**`tests\` 只留在維護者電腦、不隨公開原始碼附上**（2026-10-12 起）；本節與 E 節提到的測試檔都在那裡。
`build_exe.bat` 打包前會全部跑一遍；也可以單支執行：

```
python tests\smoke.py
python tests\test_r4_kinship.py
```

- **前端行為測試**：用 node 的極簡假 DOM（`tests\_fakedom.js`＋`tests\_nodedom.py`）載入真的 `index.html`、`bridge.js`、`app.js` 跑情境，
  不開任何視窗。需要 **node 18 以上**（用到內建 fetch），找不到 node 才 SKIP。
- **真瀏覽器測試**：找得到 Edge 或 Chrome 時，部分測試會再用 headless 瀏覽器跑一遍（實際渲染、列印版面）。
  不想在使用中的電腦上啟動瀏覽器時，設環境變數 `KINLINK_TEST_NO_BROWSER=1`（或 `KINLINK_SKIP_BROWSER=1`，兩者等效），所有測試的瀏覽器段都會印 SKIP。
  要做真瀏覽器實測請在「命令提示字元」或 PowerShell 跑、不要設這兩個變數；在 Git Bash 底下 Edge 渲染不出頁面，會 SKIP。
- **開源前個資守門**（`tests\test_opensource_pii.py`）：拿專案根 `繫族.db` 裡的姓名、電話、地址當字典，掃所有會進公開 repo 的檔案。
  程式內建的示範資料一律從字典扣除；專案根沒有 `繫族.db`，或庫裡只有示範資料（照 B 節先試跑過）時 SKIP 並說明，不會中止打包。
- **SKIP 不等於通過**：打包結尾的 SKIP 彙總列出哪些部分這次沒驗到，請到有 node／Edge 的環境補跑，或人工確認。

## E. 維護者注意

- **改 `.bat` 檔**：一律 CRLF 換行（`.gitattributes` 已設定）。`chcp 65001` 之後，「以中文字結尾的行」的下一行不能再含中文——
  繁中 Windows 的 cmd 會讀錯行，把碎片當指令執行。長段中文說明一律放 `.txt`、用 `type` 印出。
  `tests\test_b3_bat_dbcs.py` 會靜態檢查專案內每支 `.bat`（`tests\test_g9_build_onboarding.py` 另檢查 `build_exe.bat`）。
- **升級任何套件**：同時改 `requirements.txt`（直接相依）與 `constraints.txt`（完整版本鎖），刪掉 `build_venv` 重跑 `build_exe.bat`；
  `tests\test_g9_build_onboarding.py` 會比對 build_venv 實裝版本與 `constraints.txt` 是否一致。
- **改示範資料**：`webview/js/bridge.js`（展示模式）與 `db.py` 的 `seed_demo()`（exe 首次啟動）是兩份互不相干的資料，要改兩處；
  `seed_demo()` 另須與 `db.DEMO_SIGNATURE`／`DEMO_TOMB_SITE` 一致。示範資料一律虛構，不得放真實族人資料。
- **schema 唯一權威**是 `db.py`；新欄位一律在 `init_db()` 以 `ALTER TABLE ... ADD COLUMN` 冪等補上。

## 常見問題（FAQ）

- **Q：A、B 有什麼差？**
  A 只是看畫面（假資料、改了不存）；B 是真的用（會存進 `繫族.db`）。

- **Q：資料怎麼備份？**
  一律優先用程式內「設定 → 資料 →『立即備份』」：它會把最新資料完整合併成一個單檔，存進資料庫旁的
  `backups\繫族-備份-日期-時間.db`，複製走即可。程式另外會自動備份：每次啟動存 `自動備份_日期.db`、
  每次解鎖編輯存 `編輯前_日期_時分秒.db`（各留最近 5 份），還原或清空示範資料前也會先存一份 `繫族-備份-*.db`。
  若必須手動複製 `繫族.db`：**先完全關閉繫族程式**，並確認同資料夾沒有殘留 `繫族.db-wal`／`繫族.db-shm`
  兩個檔（還在就代表程式沒關乾淨）再複製——程式執行中直接複製，會拿到**缺最近改動的舊資料**而不自知。

- **Q：怎麼還原？**
  解鎖編輯後，「設定 →『還原備份』」，選一份備份檔（通常在 `backups\`）→ 確定。不是完整的繫族備份會被擋下，
  現有資料不動；覆蓋前會先自動備份現況。

- **Q：換電腦怎麼搬？**
  把整個資料夾（`繫族.exe`、`繫族.db`、`backups\`）複製到新電腦即可；或在新電腦用「還原備份」選備份檔。

- **Q：打包失敗（沒看到 BUILD SUCCESS）？**
  往上看錯誤訊息：找不到合用的 Python、build_venv 版本不合，都會印出中文說明照做即可；
  其餘多半是當下沒網路、套件裝不起來，或某支測試失敗（`build_venv\test-logs\` 有每支測試的完整輸出）。
  `--selftest` 失敗時，報告在 `build_venv\selftest.log`。

```
A 預覽：  webview\index.html  →  用瀏覽器開（file://，展示模式，不存檔）
B 執行：  python app.py       →  原生視窗 + 後端 + 專案資料夾的 繫族.db（開發用，存檔）
C 打包：  build_exe.bat       →  dist\繫族.exe ＋ dist\kinlink-vX.Y.Z-win-x64.zip／.exe（雙擊即用、可攜）
```
