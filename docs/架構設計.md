## 1. 為何 exe 裡是 HTML？

**因為 pywebview 把 HTML 當成「原生視窗的 UI 畫面」，前端與後端之間走本機 HTTP（127.0.0.1）通訊，整包由 PyInstaller 打成單一 exe。** UI 用網頁技術寫（同一份 HTML/CSS/JS 既能在 WebView2 視窗跑、也能在瀏覽器跑），但使用者看到的是一個普通的 Windows 視窗，不是「開了一個瀏覽器分頁」。

### 分層圖（文字版）

```
┌─────────────────────────────────────────────────────────────┐
│  ① 視窗外殼  app.py（pywebview / WebView2 原生視窗）           │
│     · 只負責啟動順序、開窗、收網，不跑業務邏輯                  │
│     · 兩段 fallback：WebView2 原生視窗 → 預設瀏覽器＋訊息框     │
│     · DPI 感知宣告、工作列圖示、啟動失敗的中文訊息框           │
└───────────────────────────┬─────────────────────────────────┘
                            │ 載入 url = http://127.0.0.1:<隨機埠>/?k=<token>
                            ▼
┌─────────────────────────────────────────────────────────────┐
│  ② 前端 webview/  （HTML / CSS / JS，純瀏覽器殼）              │
│     · index.html ＋ js/app.js（UI）＋ js/bridge.js（傳輸層）    │
│     · window.KinAPI：把 UI 動作翻成 fetch('/api/*')           │
│     · transport 偵測：http→web 打後端 / file://→mock 離線預覽   │
└───────────────────────────┬─────────────────────────────────┘
                            │ HTTP（fetch /api/*，回 JSON）
                            ▼
┌─────────────────────────────────────────────────────────────┐
│  ③ 後端  server.py（薄門面）＋ kinlink/（業務）                 │
│     · http.server + sqlite3，皆標準庫                         │
│     · 只綁 127.0.0.1:0（OS 配埠）＋ 隨機 token，免防火牆提示    │
│     · 靜態檔服務（webview/、/列印範本/*）＋ /api/* 路由          │
│     · kinlink/httpd.py 的 _check_host() 擋 DNS rebinding／CSRF │
│     · sqlite3（WAL 模式）讀寫隨身碟上的 繫族.db                 │
└───────────────────────────┬─────────────────────────────────┘
                            │
                            ▼
                  隨身碟資料：繫族.db / backups/
┌─────────────────────────────────────────────────────────────┐
│  ④ 打包  PyInstaller --onefile → 繫族.exe                     │
│     · webview/ 改名打包成 webview_assets/（避免撞 pywebview）  │
│     · WebView2 用系統內建，不打包 Chromium                    │
└─────────────────────────────────────────────────────────────┘
```

一句話串起來：**視窗外殼開窗 → 載入前端 HTML → 前端用 fetch 打本機 HTTP 後端 → 後端讀寫 SQLite → 整包 PyInstaller 成 exe。**

### 2.1 app.py 啟動序

`main()` 依序（實作與註解見 `app.py`）：

0. 參數有 `--selftest [報告檔]` → 走打包驗收 `selftest()`（見 §5），不開視窗。
1. DPI 感知宣告、設定 AppUserModelID（工作列圖示）。
2. exe 從 zip 或暫存資料夾直接執行 → 中文訊息框說明後結束（結束碼 3），連資料庫都不建。
3. 後端模組載入失敗 → 訊息框（exe 與原始碼模式各一段說明）後結束（結束碼 2）。
4. `server.init_db()`：資料夾不可寫（Program Files、唯讀隨身碟、防寫 SD 卡）、資料庫被占用、其他錯誤 → 對應的中文訊息框後結束（結束碼 4）。
5. 啟動自動備份 `auto_backup()`（失敗不致命）；`seed_if_empty()` 全新庫才灌示範資料。
6. `start_server()` 起本機伺服器；起不來 → 訊息框後結束（結束碼 5）。
7. 偵測 WebView2（查登錄檔）：有 → pywebview 原生視窗，`webview.start()` 阻塞到關窗；沒有、或原生視窗開不起來 → 開預設瀏覽器，並等使用者表示用完：
   * 有主控台（`python app.py` 在命令列跑）→ 按 Enter 結束；
   * 沒有主控台（exe 是 `console=False`；`工程師用-原始碼試跑.bat` 用 pythonw）→ 跳「用完請先關瀏覽器，再按『確定』結束」訊息框，按下才返回。
8. 收網：`srv.stop()` 停伺服器、釋放埠，行程結束。

`python server.py`（`server.run()`）是開發用的另一個入口：先 `init_db()` 開專案根的 `繫族.db`，起伺服器後開預設瀏覽器，Ctrl+C 結束。

### 後端 HTTP 路由（API 契約）

**完整清單以程式碼為準**：路由分派在 `kinlink/httpd.py` 的 `_route_get` / `_route_post` /
`_route_delete`，每條路由上方的註解即為契約。這裡不再抄一份——抄了就會腐爛。

只記幾個容易踩到的點：

* 免 token 的探活端點是 **`GET /api/health`**（不是 `/health`；打錯會落到靜態檔處理回 404）。
* 其餘 `/api/*` 一律驗 Host（loopback）與 token（`?k=` 或 `Authorization: Bearer`）。
* 寫入端點多數需編輯模式（未解鎖回 403）；例外：解鎖／上鎖、變更 PIN（`/api/lock/setpin`，改驗目前 PIN）、
  批次稱謂（`/api/kinship/batch`，唯讀）、立即備份（`/api/backup`），以及只改 `theme`／`ui_zoom` 的 `POST /api/settings`。
* `GET /api/export` 目前**只支援 `fmt=csv`**（其他格式一律回 501）。
* `POST /api/import` 收的是 **raw bytes ＋ `?mode=preview|commit` 兩階段**，不是 multipart；只收 UTF-8（含 BOM）。
* `POST /api/backup` 回 `{file, folder}`：備份檔完整路徑與所在資料夾（一律在資料庫旁的 `backups\`）。
* `POST /api/restore/upload` 收備份檔原始 bytes（前端「還原備份」走這支）；舊的 `POST /api/restore {file}` 只接受資料庫目錄或 `backups\` 內的檔。
* `GET /api/solar?d=`（農曆 `YYYY-MM-DD`）→ `{solar, lunar, problem}`：活動表單農曆欄的國曆對照，純曆法換算；`problem` 是該農曆日不存在時的中文說明。`GET /api/lunar?d=` 是反方向（國曆→農曆中文）。
* `POST /api/event` 遇到不存在的農曆日（如小月三十）回 400 並附中文說明；`GET /api/events` 每筆多一個 `problem`（農曆日不存在時是中文說明，否則 `''`）。
* `GET /api/kinship` 在長幼判不出時回 `"guessed": true`（稱謂一律「族親」）與 `"sameGen"`（雙方同輩為 `true`）。
  橋接端看的是 `sameGen`：同輩長幼不明時照給妯娌／連襟，母親橋接也照給舅舅／阿姨／外甥（含母親的堂、族兄弟姊妹，見規格 §2.2）。
  同胞手足另帶 `"sibling": true`，目前沒有程式讀它。
* `GET /api/member/{id}` 的 `children` 每筆帶 `rankKnown`：同性別手足排不出長幼時為 `false`，列印「全家族表」據此不冠長／次。
* `print.html` 原本可視為純讀取，現在有一個寫入點：開會通知「儲存開會內容」走 `POST /api/settings`（存 `meeting_notice`，需編輯模式）。
* 靜態檔另有白名單路由 `GET /列印範本/*`；絕對路徑、磁碟代號、UNC、含冒號的路徑在解析前就回 404。
* `POST /api/kinship/batch {toId, memberIds[]}` 是通知作業台 `{裔稱}` 專用的批次稱謂端點——
  **不要改成逐人打 `/api/kinship`**，一次就是全族在世的人數（上千人）。

### 業務函式放在哪（重要：與早期設計不同）

早期設計把業務邏輯規劃在 `db.py`，**實作沒有這樣走**。現況是：

* **業務函式住在 `kinlink/` 套件**（模組地圖見 `kinlink/__init__.py`）；
  `server.py` 是薄門面，把全部符號 re-export 成 `server.X` 穩定介面。
* `db.py` 只有四支公開函式：`connect()` / `init_db()` / `seed_demo()` / `backup(path)`，
  不含 CRUD、不含稱謂演算法（另有示範資料的辨識常數，供「清空示範資料」使用）。
* `get_db()`（kinlink/state.py）預設回傳 **server 門面模組**；測試或主程式可用 `set_db()`
  注入替身。測試直接 `import server` 呼叫業務函式即可，不必起 HTTP（`tests/` 兩種寫法都有）。
* 在世判定一律走 `kinlink/members.py` 的 `_is_alive`：`death_date` 為 NULL **且** `death_date_original` 空白才算在世。

> 設計取向：**傳輸（kinlink/httpd）、業務（kinlink 其餘模組）、儲存（db.py）三層分離**；
> 門面（server.py）只負責介面穩定，不承載邏輯。

## 3. 前端 web / mock 雙模：設計稿離線預覽 vs 實機接後端

`bridge.js` 在載入時偵測執行環境，決定 `KinAPI` 背後的 transport：

| 情境 | 偵測 | transport | 行為 |
| :-- | :-- | :-- | :-- |
| 實機（exe 視窗 / localhost） | `location.protocol === 'http:'` 且 `/api/state` 可達 | **web** | 所有 `KinAPI.*` 打真 `/api/*`，回真實 SQLite 資料 |
| 設計稿離線預覽（展示模式） | `location.protocol === 'file:'`，或後端不可達 | **mock** | `KinAPI.*` 回「楊家虛構示範資料」，純前端、不需後端；畫面頂端常駐「展示模式」橫幅 |

**價值：** 設計師／交接者直接雙擊 `index.html`（file://）就能看到完整 UI 與假資料流，不必先把後端跑起來；同一份前端碼放進 exe 後（http://）自動切到 web 模式接真後端，**零改碼切換**。

**實際導出清單見 `bridge.js`「對外介面 window.KinAPI」那一段的 `KinAPI` 物件**，這裡不抄。
除了常見的讀寫，還有 `addParent`/`removeParent`/`addSpouse`/`removeSpouse`/`setPin`/`checkUpdate`/`downloadUpdate`/
`clearDemo`，以及事件匯流排 `on`/`off`/`emit` 與就緒 Promise `ready`。

**mock 的守門與真機一致**（`tests/test_l4_mock_parity.py` 守；農曆日期不存在時擋存那一條由 `tests/test_m6_lunar_edges.py` 守）：設定除主題、介面縮放外需編輯模式；
生卒年存檔正規化；稱謂長幼判不出稱「族親」、離異稱前妻／前夫；`addParent` 親代性別空白時拒絕；
農曆活動日不存在時擋存；匯入預覽報告的鍵與真機相同。mock 的資料只活在記憶體，不會落地。

mock 資料一律虛構（`bridge.js` 是楊立宗→敬字輩→文字輩那一套）。
注意**示範資料有兩份且互不相干**：`bridge.js` 的 mock（file:// 直開時看到的）與
`db.py` 的 `seed_demo()`（exe 首次啟動、資料庫是全新的時候灌進去的）。改示範資料要改兩處；
`seed_demo()` 的內容另須與 `db.DEMO_SIGNATURE`／`DEMO_TOMB_SITE` 一致（`tests/test_h1_demo_clear.py` 比對前者）。

## 4. 資料流：兩次請求往返

### 4.1 查族譜（瀏覽，無副作用）

```
使用者在搜尋框輸入「長房」並按查詢
  └─ 前端 → KinAPI.listMembers({branch:'長房', q:''})
       └─ [web] fetch('/api/members?branch=長房&q=', {headers:{Authorization:'Bearer <token>'}})
            └─ kinlink/httpd.py do_GET：
                 · _check_host() 驗 Host/Origin（loopback 防 CSRF）
                 · _check_token()（secrets.compare_digest）
                 · _route_get → get_db().list_members('長房','')
                      └─ kinlink/members.py：sqlite3 SELECT（含同名識別標籤 label 組裝：
                           第N世·房頭·父名-姓名）
                 · _json([...]) 回 200 + JSON 陣列
       └─ 前端拿到陣列 → 渲染列表／樹狀圖
（[mock] 模式：KinAPI.listMembers 直接回記憶體裡的示範資料過濾後的陣列，無網路）
```

### 4.2 解編輯鎖（POST，有副作用）

```
使用者點左下角「瀏覽模式」，輸入 PIN、選房頭「長房」，按解鎖
  └─ 前端 → KinAPI.unlock('1234','長房')
       └─ [web] fetch('/api/lock/unlock', {method:'POST', 帶 token,
                       body: JSON({pin:'1234', branch:'長房'})})
            └─ kinlink/httpd.py do_POST（全程 try/except，未捕例外統一回 500）：
                 · _check_host() + token 驗證
                 · _read_json_body() → {pin, branch}
                 · kinlink/session.py unlock(pin, branch)：
                      · 比對 settings.edit_pin（出廠 0000；「任意 PIN 可解」
                        只在 mock 模式為真，web 模式是嚴格比對）
                      · 先建「編輯前」快照（backups\編輯前_日期_時分秒.db；失敗不阻斷）
                      · 設 editMode=True、記住 branch（房頭護欄範圍）
                 · _json({ok:true})
       └─ 前端切換為編輯模式 UI（頂部「編輯模式進行中」狀態列、左下角改顯示「編輯中」），
          後續寫入僅限該房頭的成員
```

編輯鎖**沒有閒置逾時**（2026-10-02 決定不做）：`_LOCK` 只記 `editMode` 與 `branch`，
直到使用者按左下角「編輯中」或狀態列「完成，鎖定」（`POST /api/lock/lock`）或關閉程式才回到瀏覽模式。
理由：前端收到 403 不會自動切回瀏覽模式，做了被動上鎖反而讓使用者在編輯到一半時看到莫名的錯誤。

## 5. 打包成 exe：步驟摘要與產物

1. **進入點** = `app.py`（呼叫鏈：`app.py` → `server.py` → `kinlink.*` → `db.py`，一般 import 即被 PyInstaller 收進來）。
2. **前端資產**：`webview/` 打包成 `webview_assets/`（**刻意改名**，避免與 pywebview 套件自帶的 `webview/` 撞名；`kinlink/paths.py` 的 `resolve_web_dir()` 在 frozen 時讀 `sys._MEIPASS/webview_assets/`，原始碼時讀專案根的 `webview/`）。`列印範本/` 與 `VERSION` 也打進 `_MEIPASS`。
3. **WebView 互通**：spec 收齊 pywebview、pythonnet、clr_loader 與 WebView2 組件；**不打包 Chromium**——WebView2 引擎由系統提供。農曆換算 `borax` 也在 hiddenimports。
4. **onefile 的理由**：避免 MOTW（onedir 散落 DLL 解壓後帶 Mark-of-the-Web，.NET 拒載 → pywebview 靜默退回 Edge）；onefile 解到 %TEMP%（無 MOTW），使用者只需 Unblock 一個 exe。代價：啟動較慢（先解壓）。
5. **其他旗標**：無主控台（`console=False`）、名稱 `繫族`、圖示 `webview/assets/icon.ico`。實際旗標與 datas 一律以 `繫族.spec` 為準。
6. **打包驗收 `繫族.exe --selftest <報告檔>`**（`build_exe.bat` 用 `start /wait` 跑）：在暫存資料夾建臨時庫、灌示範、起伺服器，實打首頁、列印頁、列印範本與幾支 API（含農曆換算），並實際載入原生視窗元件（pywebview、.NET 互通層、WebView2 組件，確認 `WebView2Loader.dll` 有打包；不開視窗，也不需要 WebView2 Runtime）；不碰 exe 旁的 `繫族.db`。結束碼 0＝全過、1＝有項目失敗、9＝逾時；報告寫進檔案（exe 沒有主控台）。原始碼模式載不到原生視窗元件時記成 SKIP。
7. **發佈檔**：`release/make_zip.py` 產 `dist\kinlink-vX.Y.Z-win-x64.zip`（exe＋先看我.txt＋LICENSE＋THIRD-PARTY-NOTICES.txt）與同內容的 `dist\kinlink-vX.Y.Z-win-x64.exe`（程式內更新器只認 release 的 .exe 附件）。版本號取自 `VERSION` 檔。

**產物（放隨身碟根目錄，或任一可寫入的資料夾）：**
```
繫族.exe          ← 雙擊即起 server + 開窗
繫族.db           ← 資料（第一次開啟時建在 exe 旁，整個資料夾複製即搬遷）
backups/          ← 備份：自動備份_日期.db（每次啟動，留 5 份）、

                    繫族-備份原檔-*.db（現有庫損壞時的原封複製）
```

原始碼壓縮檔（§6，目前以公開 GitHub repo 保存）。匯入 CSV 前沒有另外的自動快照。

## 6. 與規格第 6 節（部署方案）的對應

| 規格 §6 要求 | 本架構落地 |
| :-- | :-- |
| 單一免安裝執行檔，內嵌 HTTP 伺服器、SQLite、前端資源 | PyInstaller `--onefile`：`server.py`＋`kinlink/`(http.server)＋`db.py`(sqlite3)＋`webview_assets/` 全進 `繫族.exe` |
| 不使用 Docker | 後端全走 Python 標準庫；第三方執行期直接相依只有 pywebview（原生視窗）與 borax（農曆換算，MIT；原用的 lunardate 是 GPLv3，已於 2026-09-10 換掉），見 `requirements.txt`；完整版本鎖在 `constraints.txt` |
| 雙擊 `繫族.exe` 自動起伺服器並開視窗 | `app.py` 的 `main()`：起 `127.0.0.1:0` server → 開原生視窗載入本機網址（沒有 WebView2 才退回預設瀏覽器＋訊息框） |
| 免安裝、免系統權限、免虛擬化，任意 Windows 可跑 | 只綁 loopback（不觸發防火牆提示）；WebView2 缺則退回預設瀏覽器；資料夾不可寫時中文訊息框說明 |
| 資料庫、備份皆存隨身碟，整碟複製即搬遷 | `繫族.db`／`backups/` 皆相對 exe 所在路徑（`kinlink/paths.py` 的 `resolve_db_path()`）；WAL 模式 |
| 檢查更新、半自動換版 | `kinlink/maintenance.py`：`check_update`（只在按下時連 GitHub）、`download_update`（存 `繫族_new.exe`＋產生 `套用更新.bat`，舊版保留為 `繫族-舊版.exe`） |
| 原始碼另存壓縮檔供未來工程師升級 | **尚未產出**；原始碼以公開 GitHub repo 保存，`docs/` 的規格、架構、執行與打包說明即接手材料 |

> 連帶覆蓋 §3（編輯鎖：`/api/lock/*`＋房頭護欄＋解鎖快照）、§5（備份還原匯入匯出：`/api/backup`／`/restore/upload`／`/import`／`/export`）、§4.4（關閉：關窗時 `srv.stop()`；瀏覽器模式按訊息框「確定」）。
